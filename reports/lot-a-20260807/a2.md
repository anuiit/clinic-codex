## Caveats

- **Correctif espace de labels (voir ci-dessus)** : Correctif applique (2026-08-07, avant la premiere publication de ce rapport) : une premiere version de cette phase comparait directement le label natif retourne par le runtime deploye (espace ID legacy non contigu de prototypes.pt, jusqu'a 301 pour 286 classes) au label «recherche» de prediction_rows.jsonl (index de position contigu 0..285 dans backend/codex_model/config.json['class_names']) — deux espaces d'entiers distincts pour les memes classes, jamais traduits l'un vers l'autre. Cela produisait une deployed_accuracy artificiellement nulle (0/653) alors que la sortie textuelle (class_name) etait correcte dans la grande majorite des cas. Le correctif traduit l'index de position vers l'espace natif via DeployedRuntime._class_labels (deja charge, cout nul), verifie exact sur les 11 classes du sous-ensemble OOF (acatl, ameyalli, ayatl, chimalli, malinalli, mecatl, pantli, texcalli, tilmatli, tlacotl, tzacualli) et corrobore independamment par une execution du pipeline deploye complet (backend/codex_model/classifier.py, preprocessing + backbone DINOv2 charge localement sans reseau + projection + prototypes) sur 20 images sources reelles : 80% (16/20) de correspondance exacte du class_name predit, alors que la comparaison naive par label brut donnait 0/20 — la meme signature que le bug diagnostique sur les 653 lignes en cache. Ce test complet sert aussi de preuve independante de parite features/pipeline (item U2) : le backbone DINOv2-S/14 est verifie identique par sha256 (pin local de v9 == cache torch.hub utilise par classifier.py, aucun telechargement reseau), et l'accuracy elevee obtenue avec un pipeline d'extraction de features entierement independant des caches v9 confirme que les features en cache sont bien dans l'espace attendu.

- **Pretraitement** : Les predictions «deployees» sont calculees a partir des features mises en cache par le pipeline de recherche (base_features des caches OOF v9, backbone dinov2_vits14, image_size 224, S/14, white-pad — parite verifiee en Phase 0 face a la config du runtime deploye), et non par une relecture directe des images brutes a travers le runtime deploye. L'equivalence deploye repose donc sur cette parite de pipeline plus la preuve du gate de calibration C1 (Phase 0, check 3 : 50/50 correspondances exactes top-1, 50/50 top-3 sur le pilote 50-lignes).

- **U1 (provenance)** : Incertitude U1 (registre du plan) : le runtime deploye a potentiellement vu des sources apparentees a certaines des 653 lignes (prefixe row_id «external:» = corpus externe, provenance disjointe d'apres l'audit de provenance v8 ; prefixe «legacy:» = lignes historiques potentiellement provenance-adjacentes a l'entrainement deploye). ## Gate MDE — PRE-ANNONCE (avant les tirages bootstrap)

Les chiffres de cette section sont calcules analytiquement (ANOVA / ICC) AVANT le bootstrap ci-dessous, conformement au pre-enregistrement (B5).

| bras | ICC (diagnostique) | SE analytique (cluster) | demi-largeur 95% analytique | MDE 80% analytique |
|---|---|---|---|---|
| b0 | 0.2260 | 0.0478 | 0.0936 | 0.1338 |
| c1 | 0.2503 | 0.0501 | 0.0982 | 0.1404 |
| r2 | 0.3067 | 0.0534 | 0.1047 | 0.1496 |
| accuracy deployee (brute, pas un delta) | 0.2445 | 0.0516 | 0.1011 | 0.1445 |

Methodologie (c1) : ICC(1) diagnostique via ANOVA a un facteur non equilibre : ICC = (MSB-MSW)/(MSB+(n0-1)*MSW), n0 = correction de Kish pour tailles inegales = (N - sum(n_k^2)/N)/(K-1). SE analytique du gate MDE : estimateur de variance lineaire pour un ratio en echantillonnage par grappes AVEC REMISE (Woodruff 1971, equivalent au jackknife delete-a-group) — adapte au schema de rechantillonnage reellement utilise plus bas (K composantes tirees avec remise parmi les K disponibles, toutes les lignes d'une composante tiree ensemble) : z_k = sum_delta(k) - n_k*moyenne_globale (residu pondere par taille, somme nulle par construction) ; Var_hat = sum(z_k^2) / (K*(K-1)*taille_moyenne^2) ; demi-largeur 95% analytique = z_0.975*SE (z_0.975=1.959964) ; MDE_80% analytique = (z_0.975+z_0.80)*SE (z_0.80=0.841621), approximation normale bilaterale alpha=0.05 / puissance=80%.
